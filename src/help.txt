yate - yet another text editor

Usage:
  yate                  open the current folder (file tree)
  yate <folder>         open a folder
  yate <file>[:line]    open a file; the project is its git repository
  yate update           install the latest release (./update opens a file named update)

Options:
  -h, --help            show this help
  -v, --version         show the version

Keys (Ctrl keys only, no modes; ctrl+h in yate lists the commands with their keys):
  ctrl+h                command palette and keys: what the focused panel (editor or file
                        tree) can do right now, by section; enter runs one
  ctrl+p                find file (fuzzy)          ctrl+r   live grep
  tab in a picker       glob filter: *.ts, src/**, !*.test.ts (! excludes; kept for the
                        next search)
  up in a picker        the last search again, before typing
  ctrl+s                save                       ctrl+n   new file
  ctrl+q                quit
  ctrl+f                find in file               enter, down / up  next / previous match
  tab in the find bar   next field: the text, then the checkboxes [ ] Aa (case),
                        [ ] .* (regex), [ ] replace, and with replace ticked its text and
                        the buttons Replace and Replace all; left / right move along a
                        row, space or enter ticks a checkbox or presses a button
  ctrl+z / ctrl+y       undo / redo                ctrl+a   select all
  ctrl+c / ctrl+x       copy / cut (line without a selection; tmux buffer)
  ctrl+v                paste (newest tmux buffer inside tmux)
  ctrl+d                select word / next occurrence
  ctrl+/                toggle comment             tab / shift+tab  indent / outdent
  ctrl+left / right     10 characters (jumpChars)  ctrl+up / down  5 lines (jumpLines)
  ctrl+click            go to definition, or to the file of the path under the cursor

Menus: a key, then the key of a command.
  ctrl+g  go to         l line, d the definition, or the file of the path or import under
                        the cursor (path:line:col works; ctrl+p takes file:line),
                        left jump back, right jump forward
  ctrl+k  bookmarks     t toggle, down next, up previous, l list, c clear in this file
  ctrl+w  panes         v split side by side, s split one above the other, h j k l or the
                        arrows focus the pane on that side, w next pane, r resize (type
                        columns,rows to add: 10, -10 or 10,-2), = equal sizes, c close
                        the pane, o close the others, y scroll all panes together
  ctrl+t  file tree     t toggle, r reveal file, f focus, l lock following the file
  ctrl+l  lines         up / down move, left / right outdent / indent, d duplicate,
                        k delete
  ctrl+o  recent files  1 file tree, 2-9 recent files; ctrl+o again: next recent file

The second key works with ctrl still held (ctrl+w ctrl+v), except ctrl+c, which closes the
menu like esc. The key of a menu twice runs its usual command: ctrl+t ctrl+t toggles the
tree, ctrl+w ctrl+w focuses the next pane. Right after an arrow command, ctrl and an arrow
run it again without the menu: ctrl+g left, then ctrl+left ctrl+left. A menu pops up when
you wait (keyHintDelay). No key needs alt, ctrl+shift or a function key.

Bars and dialogs are forms: tab (or left / right) moves between their fields, checkboxes
and buttons, space or enter picks one, and a click does the same. They add no keys.

No tabs: the editor shows one file (one per pane in a split). Opening a file takes the place of the
one shown; unsaved changes ask first (Save, Discard or Cancel: left / right and enter, or
the first letter; esc stays). A file opens again
where the cursor was, and ctrl+p lists the files you had last on top.

File tree: enter open, left/right fold, f find file in the folder, g live grep in the
           folder, ctrl+n new, r rename, d delete, y copy path, shift+r refresh,
           [ narrower, ] wider (or drag the right edge; "treeWidth" in options keeps a
           width), esc editor. Above the files: [ ] changed (only changed files) and
           [ ] ignored (git-ignored files too); up from the first file reaches them,
           left / right move, space or enter ticks, down goes back to the files.

Settings: ~/yate.json, overridden by yate.json files closer to the working directory
          (theme, options, keys, plugins); yate.jsonc works too. "Open yate.json" in
          the palette creates ~/yate.jsonc listing every key binding, ready to edit.
Plugins:  ~/.config/yate/plugins/<name>.js (JavaScript), loaded when yate.json has
          "plugins": { "<name>": true }.
Log:      ~/.local/state/yate/yate.log
Updates:  checked once a day; "updateCheck": false in options or YATE_NO_UPDATE_CHECK=1
          turns the check off.
