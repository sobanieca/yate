yate · yet another text editorv0.5.0 · early

A terminal editor between nano and neovim.

Simple to use like nano: no modes, type and the text goes in, and the keys show on screen. Ready for a whole project like neovim: a file tree, Ctrl+P, live grep, split view, go to definition and JavaScript plugins, with nothing to set up. One binary with no runtime dependencies, for quick, comfortable edits in a terminal or a tmux pane.

$curl -fsSL sobanieca.github.io/yate/install.sh | bash
Linux and macOS · x64 and arm64 36 languages with tree-sitter No modes, no language servers UTF-8, LF or CRLF kept 

        
[yate] 0:yate* 1:shell-~/code/yate

      

      

    

  


  

    

      

        
Everything a quick edit needs

        
The project tools you reach for every few minutes, without modes, plugins to install or a config to write first.

      

      

        
Fuzzy file finder 
Type a few letters of a path and open the file. The index respects .gitignore and fills in the background.

        
Live grep 
Results update as you type across the whole project. Press Tab to narrow the search with globs like src/**/*.rs, !*.test.rs, or press g on a folder in the tree to search only there.

        
File tree 
Git status colors, checkboxes for changed files only and for ignored files, new, rename, delete and copy-path keys, find file or live grep in the selected folder, and sideways scrolling so deep names stay readable in a narrow tree.

        
Go to definition 
Jump to a function, class or variable in the file, through ES imports and re-exports, or across the project. On a path or an import it opens the file. No language server needed.

        
Syntax highlighting
Tree-sitter grammars for 36 languages are compiled in and parsed incrementally, so highlighting stays exact while you type.

        
Command palette 
Lists only what the focused panel can do right now, grouped in sections: File, Edit, Search, Go to and so on, each command with its keys. Search by section or name, bind any command to a key, or run it from a plugin.

        
Few keys, Ctrl only 
A handful of direct keys for what you do all the time, and six menu keys for the rest: Ctrl+G go to, Ctrl+K bookmarks, Ctrl+W panes, Ctrl+T file tree, Ctrl+L lines, Ctrl+O recent files. A letter or an arrow picks the command; the menu shows when you wait. No Alt, function or Ctrl+Shift keys.

        
Switch with Ctrl+O 
Ctrl+O then 1 focuses the file tree, 2-9 show a recent file; wait and the numbers pop up. Press Ctrl+O again to walk through the recent files.

        
Split view 
As many panes as you need, side by side or one above the other: several files, or several places in one file with their own cursors. Panes share the space evenly until you resize one. Scroll sync moves all panes together.

        
JavaScript plugins
An embedded QuickJS engine runs the plugins you switch on in yate.json: register commands, bind keys, react to saves, run programs.

        
Made for tmux
Copies go to the tmux paste buffer, paste reads it, and the editor dims when the pane loses focus. No key needs Ctrl+Shift.

        
Themes in yate.json
Tokyo Night (storm, night, moon, day), gruvbox (dark, light), nord and solarized-light presets. Override any palette color or syntax scope, per user or per project.

Install and update

            
The install script downloads the release binary for your system to /usr/local/bin. If you can't write there, pipe it to sudo bash, or pick another folder on your PATH:

            
# Linux and macOS, x64 and arm64
curl -fsSL sobanieca.github.io/yate/install.sh | bash
curl -fsSL sobanieca.github.io/yate/install.sh | INSTALL_DIR=~/.local/bin bash

            
Binaries for every version are on the releases page. yate checks for a new release once a day and shows a message when one is out, also after you quit. Install it with:

            
yate update        # sudo yate update when the binary is in a system folder

            
Turn the check off with "updateCheck": false in the options of yate.json, or set YATE_NO_UPDATE_CHECK=1.

            
From source

            
cargo yate              # run from source in the current folder
cargo yate src/main.rs  # open a file
cargo install --path .  # install to ~/.cargo/bin
cargo dist              # static binary in dist/yate

          


          

            
Opening files and projects

            

              
CommandOpens

              
                
yateThe current folder, with the file tree and a welcome screen of the main keys.

                
yate <folder>That folder as the project.

                
yate <file>[:line]The file, at a line if you give one. The project is the file's git repository.

                
yate updateInstalls the latest release. Use ./update to open a file named update.

                
yate --help / -vThe key list, or the version.

              
            

            
Paths everywhere in yate are shown relative to the project root. git is optional: without it you lose the git status colors and gutter signs, and everything else works.

            
yate edits UTF-8 only and keeps LF or CRLF line endings as they are. A file that is not valid UTF-8 opens read-only. When a file changes on disk, yate reloads it, or warns you when the file has unsaved changes.

          


          

            
The screen

            
From left to right and top to bottom: the file tree (toggle it with ), the editor with line numbers, git signs and indent guides, and the status line with the path of the file. There are no tabs: the editor shows one file, or several in a split, each with its path above it.

            
The status line starts with a label that tells you where your keys go. It is the closest thing yate has to a mode, and it changes only when focus moves. Each focus area has its own color, and the title of the focused panel takes it too:

            

              
LabelFocusLeave with

              
                
EDITThe editor. Typing inserts text.—

                
TREEThe file tree. Letters are tree commands.

                
PICKA picker: files, grep, palette, bookmarks.

                
FINDThe find and replace bar.

              
            

            
After the label: the git branch, the file with a ● when it has unsaved changes, messages, and on the right the language, encoding, line ending, scroll position and line:column. A message that needs the room hides the file details for a moment; one that still does not fit, or has several lines (an error in yate.json or a plugin, git blame), opens in a dialog:  scroll it,  or Enter closes it.

            
In the gutter, a bar marks lines added or changed since the last commit, and a low mark shows where lines were deleted. Colors written as #rrggbb are drawn in their own color.

Mouse

            
Click to place the cursor, Shift+click to extend, drag to select (the view scrolls at the edges), double-click to select a word, Ctrl+click to go to a definition or a file. Click a tree row to open it, a picker row to pick it, another pane of a split to focus it. The wheel scrolls three lines per step (mouseScrollLines).

          


          

            
PICK Finding things

            
Pickers open in the middle of the screen with a prompt, a result count and a list. Type to filter.

            

              
KeysPicker

              
                
Find file. Fuzzy match on the path; matched letters are highlighted. Add :line or :line:col to open the file there; a path outside the project opens too. Before you type, the files you had last are on top.

                
Live grep. Searches file contents as you type; Enter opens the file at the match.

                
f gIn a folder. In the file tree, f finds a file and g greps in the selected folder (a file's own folder). Globs then match paths inside that folder.

                
Command palette. What the focused panel can do right now, in sections. In the editor: File, Edit, Search, Go to, Bookmarks, View, File tree, Plugins and yate. In the file tree: the commands for the selected file or folder, the tree, search and yate. Commands with nothing to work on are left out (the split commands without a split, Find next without a search, bookmark navigation without bookmarks). Typing matches the section and the name, so tree toggle finds File tree → Toggle. Every command shows its keys, also the ones behind a menu (ctrl+g d), and the last section, Keys, lists the keys that are not commands.

                
Bookmarks.

                
The last search again. In find file and live grep, before you type or move: the query and the results you had last. Resume last picker in the palette brings back any picker.

              
            

            
Inside a picker:  or  or  move,  jump a page,  opens,  closes. In find file and live grep,  moves between the search and the glob field.

            
The glob field takes comma-separated gitignore globs: *.ts keeps TypeScript files, src/** or src keeps a folder, and a leading ! excludes: !*.test.ts, !dist. Plain globs and ! globs combine: *.rs, !tests/**. The glob stays for the next search until you clear it.

TREE File tree

            
 pops up the file tree menu: t shows or hides the tree ( does too), r focuses it on the current file, f focuses it, l locks it. The tree follows the file you are editing unless it is locked. Two checkboxes above the files choose what it lists: [ ] changed keeps only the files git reports as changed, [ ] ignored adds the git-ignored ones. On narrow terminals (below 200 columns) opening a file closes the tree. When a deep name does not fit, the tree scrolls sideways, hiding indentation on the left, so the selected name stays readable. [ and ] make the tree narrower or wider, and so does dragging its right edge with the mouse; treeWidth in options keeps a width, and File tree: automatic width in the palette fits the names again.

File names take their git status color: modified, added, untracked, deleted. Set nerdIcons to true for Nerd Font file icons.

            
yate has no diff or review view: use git diff, your git tool or a coding agent for that. The bundled Git: Blame current line command (palette) shows the commit, author, date and summary of the cursor line in a dialog; Esc closes it.

          


          

            
The bar is a form, so it has no keys of its own to remember: a click on a checkbox or a button does the same as Space, and typing while a checkbox has the focus goes back to the find text.

            
Files, jumps and bookmarks

            
    
              
  • One file per pane. yate has no tabs, no buffers and nothing to close. Opening a file shows it in place of the current one. When the current one has unsaved changes yate asks first with the buttons Save, Discard and Cancel:  and  choose one, the first letter of a button presses it, Esc stays. A file opens again where the cursor was. To get back to a file use ,  (the files you had last are on top) or .
    • 
              
  • Ctrl+O.  waits for a digit: 1 focuses the file tree, 2-9 show the recent files, the latest first (2 is the current file, 3 the one before). Wait a moment (keyHintDelay, 500 ms) and the numbered targets pop up. Pressing  again shows the next recent file. Esc cancels; any other key leaves the switcher and does its usual job.
    • 
              
  • Split view.  pops up the panes menu: v splits the focused pane vertically (two panes side by side), s horizontally (one above the other). Split again for more panes, in any mix. Panes split the same way share the space evenly. r resizes the focused pane: type the columns to add, like 10 or -10, the rows for stacked panes, or both as columns,rows (10,-2); the pane next to it gives or takes them. = makes all panes equal again, c closes the focused pane and o closes all the others. Each pane has its own file, cursor and scroll, so one file can show several places at once. h j k l or the arrows move to the pane on the left, below, above and on the right (the one level with the cursor), w to the next pane (), a click to any pane. y turns scroll sync on: scrolling one pane scrolls the others by the same number of lines, handy to read two versions side by side. When the terminal gets too small for the panes, only the focused one is shown.
    • 
              
  • Go to.  pops up a menu: l asks for a line number, d goes to the definition, ← and → walk the jump list. Esc closes the menu.
    • 
              
  • Go to definition.  or Ctrl+click. On a name, yate finds its definition with tree-sitter: in the same file (the innermost scope wins), in the module an ES import points to (following re-exports and export *), or anywhere in the project; several matches open a picker. On a definition it lists the other definitions with that name. On a string, an import or a path:line:col it opens the file. Imports resolve like Node and TypeScript: extensions, index files, tsconfig.json/jsconfig.json paths and baseUrl, package.json imports and exports, node_modules and @types. Definitions are found in JavaScript, TypeScript, Rust, Go, Python, C, C++, Java, C#, Lua, Ruby, PHP, Elixir, Dart, Gleam and Swift; in other languages the name opens live grep.
    • 
              
  • Jump list. Opening a file, going to a definition, picking a grep result or going to a line records where you were.  goes back,  forward; right after,  go on without the menu.
    • 
              
  • Bookmarks.  pops up the bookmark menu: t toggles a bookmark on the line, ↓ and ↑ go to the next or previous one, l lists them across files, c clears the ones in the file.

tmux and the clipboard

            
Copy and cut write to the tmux paste buffer, and paste reads the newest one, so text moves freely between yate, the shell and other panes. With set-clipboard on in tmux the copy reaches the system clipboard too. Outside tmux yate uses OSC 52.

            
When the terminal or the tmux pane loses focus, the editor background dims, like an inactive tmux pane.

            
Menus:  go to,  bookmarks,  panes,  file tree,  lines. The second key works with Ctrl still held (); only Ctrl+C differs and closes the menu, like Esc. The key of a menu twice runs its usual command:  toggles the tree,  focuses the next pane. Right after an arrow command, Ctrl and an arrow run it again without the menu, until another key or a second and a half. The popup shows only when you wait (keyHintDelay). To skip a menu, bind its command in yate.json, for example "ctrl+e": "goto.definition".

            
Every default key is Ctrl and a letter, so it works in every terminal, through tmux and in Termux. No Alt keys, which terminals and window managers often take. No Ctrl+Shift, which terminals send only with the kitty keyboard protocol (kitty, WezTerm, foot, Ghostty) and never through tmux. No Ctrl+B (the tmux prefix), and no Ctrl+I or Ctrl+M, which are Tab and Enter to a terminal. Shift+Tab is never the only way:  outdents. Bars and dialogs add no keys: the find bar and the questions yate asks are forms with checkboxes and buttons, moved through with Tab and the arrows.

Configuration

            
yate.json holds the theme, options, key bindings and plugins. It is JSONC: comments and trailing commas are allowed, and the file can be named yate.jsonc too. yate reads ~/yate.json first, then every yate.json from / down to the working directory; in each folder yate.jsonc comes after yate.json. Closer files win, key by key, so a project can set tabSize and keep your theme. A project yate.json is data only and safe to commit.

            
Open yate.json in the palette opens the closest file or creates ~/yate.jsonc from a commented template. Saving it applies the change at once. Mistakes show with file, line and column in the status line, or in a dialog when there are several.

            
{
  "theme": {
    "preset": "tokyonight-night",
    "colors": { "bg": "#1e1e2e", "orange": "blue" },   // a color can copy another one
    "syntax": {
      "keyword": "magenta",
      "comment": { "fg": "#6c7086", "italic": true }
    }
  },
  "options": { "tabSize": 4, "nerdIcons": true },
  "keys": {
    "editor": { "ctrl+y": "tree.toggle", "alt+z": "edit.redo" },
    "global": { "ctrl+q": "" }   // "" or null removes a binding
  },
  "plugins": { "date": true, "format": false }
}

            
Theme presets

            

            
colors overrides palette colors such as bg, bg_dark (tree, bars, pickers), bg_visual (selection), blue (accents) or git_add. syntax styles tree-sitter scopes such as keyword.return or function.method; the longest matching scope wins, and a value is a color or an object with fg, bg, bold, italic and underline.

Keys

            
Bindings are grouped by context: global, editor and tree. A context binding wins over a global one. Key names look like ctrl+p, alt+shift+down, f5 or ctrl+/; values are command ids from the key reference or from plugins.

            
Plugins

            
"date": true loads ~/.config/yate/plugins/date.js; a plugin file that no yate.json switches on is not loaded. The bundled git and format load unless set to false. See Plugins.

            
The full reference, with every palette color, is docs/configuration.md.

          


          

            
Plugins

            
yate runs JavaScript in an embedded QuickJS engine. There is no Node.js and no npm: a plugin is one .js file in ~/.config/yate/plugins with a global yate object. It loads when the plugins section of yate.json names it: "date": true loads date.js. yate loads the bundled plugins first, then yours in name order. Saving a plugin reloads everything.

            
Plugins load only from your config folder, never from the opened project. A plugin can run programs, and opening a repository must not run its code.

            
// ~/.config/yate/plugins/date.js, on with "plugins": { "date": true }

// A command shows in the palette and can be bound to a key.
yate.registerCommand("date.insert", "Insert today's date", () =>
  yate.editor.replaceSelection(new Date().toISOString().slice(0, 10)),
);
yate.bindKey("alt+d", "date.insert");

// Format with Prettier before every save of a TypeScript file.
yate.on("beforeSave", () => {
  if (yate.editor.language() === "typescript") yate.runCommand("format.prettier");
});

            
How a call works

            
Before a plugin function runs, yate takes a snapshot of the text in the editor. yate.editor reads that snapshot, and changes are queued and applied in order when the function returns. Lines and columns are 0-based. async functions work, and a call longer than 10 seconds is stopped.

Languages

            
Highlighting comes from tree-sitter grammars compiled into the binary. The language follows the file name; change it for the file in the editor with Set language of file in the palette.
